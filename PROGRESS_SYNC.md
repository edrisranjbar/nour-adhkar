# Android progress backup and sync

`POST /api/progress/sync` requires the existing account JWT (including Google sign-in), is rate limited to 10 requests/minute, and accepts version 1 per-item records. Records are scoped to the authenticated user, never to a client-supplied user ID. Streak activity days, checklist membership, history, counters and reading progress are supported; credentials, location, installation identity, notification settings and downloaded audio are excluded.

Records contain `key`, millisecond `modified`, UUID `device`, `deleted` and `value`. Newer records win; equal timestamps use lexicographical device UUID order. Deletion tombstones remain to prevent stale devices resurrecting removed items. Concurrent uploads lock the owning user inside a transaction. History uses deterministic hashes so restoring or retrying does not duplicate sessions. Payload and stored backup sizes are bounded; unsupported versions or malformed records fail without updating the backup. Deleting the account cascades to its backup.

Android sync starts automatically for every signed-in account; there is no enable/disable setting. The profile exposes status, manual retry and last successful sync time. Offline edits are journalled before requests and retried while the app is in use, approximately every 30 seconds. Sync is not guaranteed while the app is closed. Signing out stops requests and retains local progress and the existing server backup.

The `Deploy` manual workflow with `progress_sync_only=true` can deploy this feature from `develop` without merging into `main`. It runs focused backend tests, applies only the endpoint/controller/migration patch against production, checks that the patch applies cleanly, runs only its migration and refreshes routes/FPM. It does not reset the server checkout or deploy unrelated develop changes. The applied patch remains visible in the server worktree until the regular main deployment contains it; never discard it before that merge. Existing schema/data and unrelated local server edits are preserved. Re-running an already applied patch is supported.
